# PRIMEngine: notes for Claude

- Owner (Kiru) does not code; they direct, make art/audio and test. Explain in plain English; do the coding.
- Plain classic `<script>` files on a global `PRIM` namespace. No bundler, no ES modules, no third-party libs.
- `index.html` is PRIMEngine Studio (project manager + screen editor). `legacy-editor.html` is the old Metroid-style test editor (still works, uses src/engine, src/game, src/editor).
- Studio: EVERY value is a tag (`src/core/tags.js`), named `screen.element.property` or `audio.master`. Structure (screens, element ids) is separate from values. Renaming an element moves its tags and fixes references.
- Project file = `.prime` (a ZIP: project.json + Assets/ folders), see `src/core/prime.js`, `zip.js`. Browser autosave copy lives in localStorage; imported files in IndexedDB (`src/core/store.js`). `src/core/host.js` handles save/open/pick-folder (Electron via `window.primeDesktop`, else File System Access API with download/<input> fallbacks).
- Maps (`project.maps`) are GRID maps (EasyFPS style, `src/core/grid.js` = `PRIM.Grid`): `{id, style:"grid", w, h, layers:[{cells:{"x,y":cell}}], things, n}`. One cell = 128 units = 2 m, one layer (story) = 128 units tall. Cell keys: `w` wall block texture ("" = default look, `ws:{0..3}` per-side textures, 0 N 1 E 2 S 3 W), `f` floor texture + `h` 0..15 (16ths, 8 units each), `sh` "slope"|"stairs" + `sd` rise direction + `sr` rise 1..16 (stairs = 8 steps), `c` ceiling (at layer top - 1), `li` light %, `dg` diagonal/partial wall = solid polygon [[u,v]...] in the cell (0..1, u east, v south) + `dt` its texture (`G.SHAPES`: 45°, 26° (2 cells), 18° (3 cells), 63°, small/big corner cut, half block, edge wall; `G.shapeCells(id, rot, flip)`; built as a prism, info kind "diag"). Cells are STRUCTURE (not tags); map settings are tags (`Schema.MAP`: sky, fogOn/fogColor/fogStart/fogEnd, mood preset (`R3D.MOODS`) or custom moodTint/Brightness/Contrast/Saturation, startX/startY/startLayer/startAngle). World: X = x*128, Z = y*128, Y up. Old room/node maps are deleted on load (`ensureWalls`, owner: start fresh); the Wall Editor, wallmesh.js and mapgeo.js are gone.
- Screens are drawn by `src/core/runtime.js` (DOM, 1280x720 stage). Studio UI (`src/studio/studio.js`, CSS in index.html) copies classic Unity: Hierarchy, Scene/Game, Inspector (+Tags), Project explorer, Console; skins `dark` / `light`.
- TARGET IS WINDOWS ONLY for now (owner decision). Mac/Linux builds come after the Windows app is finished; do not spend time on them.
- Desktop app: `desktop/` (Electron). Built on GitHub by `.github/workflows/build-desktop.yml` (push to main = Actions artifacts; tag `v*` = Release). npm is NOT reachable from the Claude sandbox, so desktop builds can't be tested locally.

- Player (`project.player`, tags `player.*`; schema in `schema.js` S.PLAYER/S.ATTACH): walking/collision/jump/sprint/crosshair/aim modes (classic, free = bodycam) in `src/core/play3d.js`; HUD = a screen of kind `hud` drawn over the game. Player Editor tab attaches FBX models to the camera (`player.att1.*` tags); a weapon has a muzzle point + arrow that turns toward the crosshair raycast.
- FBX: `src/core/fbx.js` (ASCII + binary, rigid node animation only, no skin weights), math in `math3d.js`. Animation blending: `F.local(model, anim, t)` (per node t / quaternion q / s), `F.mixLocal(a, b, w)`, `F.world(model, local)`; `Play3D.mixPose(holder, model, name, time, dt)` eases from the last shown pose into a new animation (or a restart, flagged by `playAnim` via `at.restart`) over tag `player.animBlend` seconds (default 0.15, Player Editor > Feel), used for weapons/objects (`drawHand`) and placed things (doors, enemies, decorations). Test: `s_blend.js`. Timeline tab: sound events per model animation, stored as `project.events=[{id,asset,anim}]` + tags `ev1.time/sound/volume`; played by `Play3D.ev()` in game.
- Tests: `tools/dev/s_att.js` (attach/aim), `s_tl.js` (timeline + in-game sounds), `s_player.js`, `s_grid.js`, `s_unity.js`.
- Screen positions (`x`,`y` tags of screen elements) are measured from the MIDDLE of the 1280x720 stage (x0,y0 = middle, y up). `project.origin==="center"`; `Schema.toCenter` converts older projects in `Store.migrate`. Edit mode in runtime.js has a corner resize handle (`rt-handle`) and the inspector has Center buttons.
- Player objects (`project.player.attachments`, tags `player.<attN>.*`) have a `type` tag: weapon (numbered weapon list, 1-9 / wheel switch, muzzle + arrow), animation (FBX model) or image (flat quad via `FBX.loadImage`). Object editor = `objectCenter()` in studio.js (click to place muzzle, drag to aim arrow).
- Hierarchy folders: `project.hfolders=[{id,name,scope?}]`, items carry `.folder`; scope = a screen id means a folder of that screen's elements.
- Tests also: `s_obj.js` (objects, weapon switch), `s_fold.js` (folders), `s_hud.js` (origin, resize handle, migration).
- Node Coder (tab "Node Coder"): one script per object, stored on it as `script={nodes:[{id,type,x,y}],links:[{a,o,b}]}` (screen element nodes and `project.player.attachments`). Node values are tags `<owner key>.s.<nodeId>.<value>` (owner key = `screen.element` or `player.attN`). Node types live in `Schema.SNODES`; runner = `src/core/script.js` (`PRIM.Script.Host`, async chains with wait/if/repeat). Hooks: `Runtime.script()` for screens (onStart/onClick/onKey), `Play3D.trigger()` for player objects (onStart/onClick/onKey/onEquip; a weapon only hears events while it is the current weapon). The old per-weapon "click animation" tag was replaced by a script (`ensurePlayer` migrates it). UI = `coderCenter()` in studio.js.
- Objects have a free pivot (`pivotX/Y/Z`, model space): position, rotation and scale act around it; set it with the "Set pivot" tool of the object editor.
- Tests also: `s_code.js` (node coder).
- Node conditions: every node has "Only if…" tags `<owner>.s.<node>.needTag/needOp/needVal` (`Schema.SCOND`, created by `defineSNode` / `ensureSNode`, also for screen-element scripts). `Host.ok(owner, n)`: events whose condition fails don't fire (`trigger`), a chain stops at a failing node (`chain`), `Play3D.charge` won't start charging. Node cards show 🔒, the inspector has an "Only if… (condition)" foldout. bool tags accept yes/no/true/false/1/0. Test: `s_cond.js`.
- Asset explorer multi-select (`studio.js`): `S.sel` is the primary item, `S.multi={primary,items}` the set (ctrl/shift-click via `clickPick`, rubber-band via `marquee`, `topLevel()` drops items inside a selected folder); multi drag/drop uses `dropOne`, delete uses `deleteAssetSel`. Tests: `s_multi.js`, `s_size.js` (width/height fields, proportions, corner handles).
- A Play3D shuts itself down (`destroy`, guarded) as soon as its root is no longer on the page (`frame` checks `root.isConnected`; key handler ignores keys meanwhile), and Studio `stopPlay()` ends `S.play` on project close / Maximize-on-Play close: stopped playtests used to keep running invisibly and stack footsteps. Test: `s_replay.js`.
- Game view (`Play3D.bind`) has a `.p3leave` button shown whenever the mouse is free. Images have a `stretch` tag ("Stretch to screen", fills the 1280x720 stage). Tests: `s_stretch.js`, `s_leave.js`.
- Keys: `Schema.KEYS` (dropdown list incl. mouse1/2/3 = left/right/middle). Node types onKey, onKeyUp, onHold (interval), ifKey; hold/up/ifKey are player-object only. Play3D: `press/release/hold`, footsteps never overlap (`footstep`: >= 0.2 s apart, not right after landing, cuts the previous step's tail), player sound tags (footstep*, jumpSound, landSound, hurtSound, deathSound, soundVolume). Tests: `s_input.js`, `s_input2.js`.
- Weapons: projectile settings (`projType` none/hitscan/particle/mesh, `proj*` tags) and a projectile emitter point+arrow (`emitX/Y/Z`, `emitYaw/Pitch`, object editor tools "Set projectile emitter"/"Aim emitter arrow"). Nodes `onCharge` (shown as "Charge weapon"; outs start/charged/fire/cancel; `Play3D.charge`, live tag `player.charge`) , `chargeShow` + `chargeGrow` (charge particle at the emitter, `Play3D.orb`; the released projectile keeps its size) and `fireProjectile` (`Play3D.fireProj`, FX drawn by `View.drawFx`). Node Coder: Shift+A opens the add menu (`S.coderMenu`), categories are submenus (`menuEl` supports `sub`). Test: `s_charge.js`.
- Timeline: animation length overrides `project.animLen=[{id,asset,anim}]` + tag `<id>.length` (`Schema.animLen`, `Play3D.animLen`; sound times are in the adjusted seconds; orange handle drags the length); sounds are bars with waveform (`waveOf`), Shift+drag / wheel = volume. Test: `s_len.js`.
- Player feel: tags `player.breathe*`, `bob*`, `hudMove`/`hudMoveAmount` (`Play3D.feel`: viewmodel offset `vmOff` + HUD sway via `hud.sway(x,y)`); player state (standing/walking/running/jumping/falling, groups moving/inair) = live tag `player.state`, nodes `onState` + `ifState` (`Schema.STATES`, `Play3D.setState/isState`). Test: `s_feel.js`.
- Renderer: `render3d.js` `rebuild` = `Grid.build(map)` (batches per texture x 8x8-cell chunk, frustum culled via `visible()`) + `Grid.index(tris)` -> `View.world`; `View.raycast` = `Grid.raycast` (DDA over 256-unit cells) + `View.extraTris` (closed doors). Shader: up to 8 lights (point / area), material = tint + base colour map (`tex`) + emission (`emitK`, optional `emitTex` map, else the albedo glows) + flat `emit` for effects; then mood grading (`lookUniforms`: tint x brightness, contrast, saturation) and linear fog (`fogS..fogE`, off for the viewmodel). Materials of objects/props: ONLY `matTexture` (base colour map), `matEmitMap`, `matEmit` (`Schema.matOf` -> {emitK, texId, emitTexId}; old PBR/tint tags are deleted on load).
- Scale: 64 units = 1 m, cell 128 = 2 m, story 128. Eye height 102. Physics (`Grid.push/move`): the player/enemies are capsules (feet at pos, r, h = eye+8 capped to story-6) sliding on the collision triangles; faces are ONE-SIDED (`tri.f` = open side), the upper body is narrow against ceilings (stairwells work), step-up probe + gradual settle, ground snap, `squeeze` blocks moving where the head does not fit. Sub-steps: sideways <= 0.6 r, vertical <= 0.25 r (else the narrow head tunnels through ceilings when jumping). Upper-story floors get a hidden downward collision face (info.hidden: collision only) when nothing is under them. Max walkable slope cos 0.69 (a full 16/16 slope = 45 deg).
- Audio nodes: `loopSound` / `stopLoop` (Script host callbacks `loop` / `stopLoop`; Runtime + Play3D keep one looping Audio per sound, stopped on destroy). Test: `s_loop.js`.
- Objects (tab "Object Editor", `propCenter()`/`propInspector()` in studio.js): `project.props=[{id}]`, schema `Schema.PROP` (tags `<propId>.name/type/asset/scale/rx..oz/idleAnim`, door: `doorHeight/openMode(interact|proximity|shot)/openRange/interactRange/openAnim/closeAnim/autoClose/closeAfter/openSound/closeSound`, pickup: `giveTag/giveAmount/pickRadius/pickSound`). Type = decoration / door / pickup. Editor shows the 16x16 cell grid, doorway block and its wall boxes; "Scale to grid" / "Center on grid". Types: decoration / door / pickup / enemy / exit / npc.
- Placed objects live in `map.things`: `{id, prop, x, y, ang, layer}` (world units; a door is anchored at the clicked cell and is a block `doorCellsW` cells wide (running along `ang`: 0 east, 90 south, 180 west, 270 north) x `doorCellsH` stories tall, reaching the top of its last story; `doorFit` (default on) stretches the model to fill it exactly (`Play3D.doorFit`, depth <= 16) and the sliding door is clipped at the doorway top (shader `uClipY`, mat.clipY) so it never pokes through). `Grid.thingFrame(m,T,th)` -> {cx,cy,fy,ux,uy,nx,ny,w,h,thick,door,cells,W,H}; closed doors are `Grid.boxTris(Grid.doorBox(f))` collision (`Play3D.doorTris`). `player.interactKey` (default E).
- Runtime: `Play3D.syncThings/thingStep/drawThings` (door state machine closed/opening/open/closing, FBX openAnim/closeAnim or slide-up fallback, `hitDoor`/`shootDoor` for shot mode (hitscan + projectiles), `interact()`, proximity, autoClose; `doorOpen` makes `push` ignore the door wall segment; pickups add `giveAmount` to tag `giveTag`). Tests: `s_door.js`, `s_place.js`.
- Fly Editor (tab "Fly Editor"): hold RIGHT mouse + WASD to fly, left-click picks a face (`raycast` info {kind wall|walltop|floor|ceil, layer, x, y, side}), Shift adds; `flyInspector()` sets the texture of the selected faces (a wall side -> `ws[side]`, "every side" -> `w`); images can be dropped on a face (`flyDrop`).

- Audio engine (rebuilt): `src/core/audio.js` = `PRIM.Audio` (Web Audio). `load(url)` decodes once (cache) and finds the real sound inside the file (skips encoder silence at start/end, <= 0.3 s, below ~-60 dB); `play(url, vol, loop)` -> handle {stop(fade), setVolume(v), playing}; loops are sample-exact (`loopStart/loopEnd` = trimmed part). Falls back to <audio> if decoding fails. Used by runtime.js (sfx, loops, music), play3d.js (`vol3`, `sfx`, `loopSfx`, timeline events; preloads all sounds at start), hud.js and Studio previews. Tests hook `PRIM.Audio.play` (`s_audio.js`, `s_loop.js`, `s_tl.js`).
- Gameplay (objects): Object types `enemy` (tags health/speed/radius/height/sight/attack melee|hitscan|projectile/attackRange/damage/attackRate/attackDelay/proj*/walkAnim/attackAnim/hurtAnim/deathAnim/corpse/sounds/killTag/killAmount) and `exit` (exitTo map|screen, exitMap (type `mapRef`, empty = next map), exitScreen, exitRadius, exitSound). - NPCs: prop type `npc` (tags npcName, talkRange, radius, talkAnim / talkSprite(+Frames), faceTalker). Dialogue = structure `prop.dialog.lines=[{id}]` + tags `<prop>.d.<line>.speaker/text/sound/next` and choices `c1..c4 text/go/tag/val` (`Schema.DLINE`, `addDLine/removeDLine`, `syncDOpts` refreshes the go-to options: next / end / any line). NPCs block the player (`push`). Test: `s_npc.js`.
- Renderer goals (owner): PC engine, push rendering far, "modern retro" look (crisp pixel textures + modern light). Post-processing will later get its own tab "Compositor" (like Blender's); hook it into `present()`.
- Real-time shadows: lights with `shadow:true` (lamp objects, projectiles, charge orb; NOT lights you carry) get a cube map of distances (packed RGBA, program `spr`, `renderShadows` before the frame: up to `shadowCount` 3 (max 4), lamps first; lamp maps (key = owner thing id, 512) are cached and redrawn every 3rd frame or when moved; moving lights share 256 maps). Main shader samples `uSh0..3` (units 2-5) in the light loop for `uShL` lights, 4-tap soft compare. Casters = level chunks in range + `view.casters` (the drawFx mesh items of things, set by `drawThings`; a lamp's own model never shadows its own light via `owner`). Setting `gfx.shadows`.
- HDR + bloom: `view.post = true` (Play3D play mode) -> `draw()` renders into a half-float picture (`setupPost`, falls back to 8-bit), `present()` (called at the end of `Play3D.frame`) = bright pass (half res) -> blur half + quarter -> composite with exposure and a soft roll-off above 0.8. Map tags `bloom/bloomStrength/bloomThreshold/exposure` (Look foldout), setting `gfx.bloom`. Views without post (editors) draw straight to the screen.
- Light picking (`pickLights`): a light is used when its sphere touches the view (frustum) and is within fog range, nearest first, max 8, so projectile lights keep lighting the level however far they fly. Auto-LOD (`lodOf`) never simplifies meshes under 3000 vertices (small projectiles used to collapse into flat cards).
- Light-giving objects: prop tags `lightOn/lightColor/lightIntensity/lightRange/lightHeight/lightFlicker/lightShadows` (Object Editor "Light" foldout); `drawThings` adds them to the frame's lights. Test: `s_render.js` (it keeps post on; `shot3.js` sets `window.__noPost` for every other test because software GL is too slow for it).
